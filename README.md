# 학교 학급별 진도 대시보드 프로그램

초등학교 선생님이 학급별 과목·단원 진도를 기록하고, 같은 학년의 진도를 함께 확인하는 프로그램입니다.

- [제품 요구사항](PRD.md)
- [설계서](docs/DESIGN.md): 역할별 권한, 화면, 데이터 구조, 진도 계산, 학기 보관, 기술 구성
- [와이어프레임](docs/WIREFRAMES.md): 주요 화면 18개, 메뉴·이동 경로, 버튼 동작, 오류·보관 상태, 좁은 화면 배치
- [개발 계획서](docs/PLAN.md): 개발 순서, 단계별 완료 기준, 요구사항별 검증 시나리오
- [로그인 실행 및 연결](docs/AUTH_SETUP.md): Supabase 설정, 인증 SQL 설치, 첫 계정 발급과 검증 방법
- [사이트 관리자 대시보드](docs/SITE_ADMIN.md): 학교 관리, 학교 관리자 지정, DB 권한과 실연결 검증
- [학년 관리자 대시보드](docs/GRADE_ADMIN.md): 학년 진도 비교, 단원·명단 조회, 테스트 계정과 실연결 검증
- [학교 관리자·선생님 대시보드](docs/WORKSPACES.md): 학교 운영·계정·학기 관리, 담당 반 진도 저장, 명단·교육과정과 권한 검증

아이디·비밀번호 로그인, 세션 보호, 로그아웃과 최초 비밀번호 변경을 제공합니다. 사이트 관리자는 학교와 담당 관리자를 관리합니다. 학교 관리자는 자기 학교의 학기·학년·학급·담당 배정·교사 계정·명단·교육과정을 관리하고, 선생님은 담당 반의 진도를 저장하며 같은 학년 진도를 비교할 수 있습니다. 학년 관리자 전용 화면은 학년 전체 명단·교육과정·진도 조회를 제공합니다. 학년 관리자용 편집 UI와 접속 통계는 후속 작업입니다. 설계서는 2026-10-07에 확정한 추가 요구사항을 반영하며, PRD와 겹치는 부분은 설계서의 확정 요구사항을 우선합니다.

실행은 `npm run dev`, 접속 주소는 `http://localhost:3000`입니다. 실제 계정 로그인에는 위 연결 문서의 Supabase 인증 SQL 설치와 계정 발급이 필요합니다.

테스트 학교는 **대시보드 테스트 초등학교**입니다. `school.admin`은 학교 관리자, `grade.admin`은 2026학년도 2학기 3학년 관리자·1반 담임, `test.teacher`는 같은 학년의 **2반 일반 담임**입니다. 기존 계정의 비밀번호는 유지합니다.
