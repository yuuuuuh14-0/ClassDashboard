# 사이트 관리자 대시보드

구현일: 2026-10-17

사이트 관리자 계정으로 로그인하고 최초 비밀번호 변경을 완료하면 `/dashboard`에 사이트 운영 화면이 표시된다. 일반 선생님은 기존 계정·배정 대기 화면을 사용한다.

## 제공 기능

- 운영 요약: 운영 중인 학교 수, 운영 중인 학교의 활성 관리자 수, 전체 활성 계정 수, 관리자 미지정 학교 수.
- 학교 관리: 학교 등록, 이름 수정, 검색·상태 필터, 8개 단위 페이지 이동, 사용 중지·복구.
- 학교 관리자: 기존 활성 계정을 학교에 연결해 관리자 지정, 새 관리자 지정 후 기존 관리자 권한 해제. 해제한 계정의 학교 소속은 유지한다.
- 최근 운영 기록: 학교와 관리자 권한 변경 6건. 실제 변경과 감사 기록은 같은 DB 트랜잭션에서 저장한다.
- 운영 안내, 비밀번호 변경, 로그아웃. 모바일의 넓은 학교 표는 표 안에서 가로 스크롤한다.

화면 수치는 실제 DB 데이터다. 활성 계정 수는 사이트 관리자와 선생님을 포함하며 접속 인원이나 오늘 이용자 수가 아니다. 접속 집계·학기·학급·학교 관리자 전용 업무 화면·웹 계정 발급은 후속 단계다. 운영 기록은 이 기능 설치 이후 변경부터 기록하며 기존 기록을 만들어 넣지 않는다.

## 학교와 계정 연결

1. `학교 추가`에서 학교 이름을 입력한다.
2. 해당 학교의 `관리자 지정`에서 기존 계정을 선택한다. 학교 미소속 계정은 이 학교의 소속 등록과 관리자 지정을 함께 처리한다.
3. 다른 학교에 활성 소속이 있는 계정은 선택하거나 지정할 수 없다. 한 계정의 활성 학교 소속은 하나로 제한한다.
4. 담당자를 교체할 때는 새 관리자를 먼저 지정한다. 마지막 활성 관리자 해제는 UI와 DB에서 모두 막는다.

학교 사용 중지는 학교와 소속·권한 기록을 보존한다. 중지된 학교에서는 관리자 배정을 변경할 수 없고, 복구하면 기존 지정이 유지된다. 교사 계정 비활성화나 학교 소속 해제와는 별도 동작이다. 계정 자체의 로그인은 기존 인증 규칙을 따르며, 향후 학교 업무 API는 학교 활성 상태도 검사해야 한다.

## DB·API 계약

- 마이그레이션: `202610170001_site_admin.sql`, `202610170002_conflict_response.sql`.
- 데이터: `schools`, `school_memberships`, 외부 API에 노출하지 않는 `auth_private.school_audit_logs`.
- `GET /api/site-admin`은 운영 요약용 스냅샷을 반환한다. `POST /api/site-admin`은 허용한 학교·관리자 변경 명령만 받는다.
- 모든 요청에서 활성 계정·최초 변경 완료·사이트 관리자 권한을 확인한다. DB RPC도 현재 프로필과 세션을 다시 검사한다. 일반 교사와 학교 관리자는 사이트 전체 조회·변경을 할 수 없다.
- 대시보드는 로그인한 사용자의 Supabase 클라이언트를 사용한다. 운영 데이터의 읽기·쓰기에 서버 관리 키를 사용하지 않는다.
- 공개 역할의 직접 테이블 쓰기를 차단하고, 사이트 관리자만 RLS로 학교·소속을 읽는다. 변경은 검증·감사를 포함한 전용 RPC만 허용한다.
- 학교 이름·상태·관리자 배정이 바뀌면 학교의 `version`을 증가시킨다. 변경 요청의 `expected_version`이 다르면 `409`를 반환해 덮어쓰기를 막는다. DB의 의도적인 충돌은 `PT409`로 응답한다.
- 네트워크 오류로 저장 결과가 불확실하면 목록을 다시 확인한 뒤 재시도한다. 조회 실패를 등록 0건으로 표시하지 않는다.

## 실행과 검증

```powershell
npm run dev
npm test
npm run typecheck
npm run test:e2e
npm run build
npm run admin:verify-live
```

실연결 검사는 `.env.local`의 프로젝트와 `http://localhost:3000`의 앱을 사용한다. 다른 주소는 `AUTH_TEST_APP_URL`과 `APP_ORIGIN`으로 지정한다. 임의 이름의 임시 관리자·교사와 학교 두 개만 생성하고 종료 시 학교·소속·감사 기록·계정을 정리한다. 기존 사용자와 학교는 변경하지 않는다.

검증 항목은 실제 학교 저장, 이름 수정과 충돌 거부, 관리자 배정·교체, 마지막 관리자 보호, 다른 학교의 소속 계정 지정 차단, 사용 중지·복구, 직접 DB/API 권한 검사, 권한 회수의 즉시 반영이다. 브라우저 검사는 별도의 모의 인증·DB 서버를 쓰며 실제 Supabase 검사를 대신하지 않는다.

2026-10-17 단위 테스트 5개, Edge 브라우저 테스트 9개, 타입 검사와 배포 빌드를 통과했다. 실제 Supabase의 학교 저장·권한·충돌·복구·감사 기록과 임시 데이터 정리를 확인했다. 데스크톱과 모바일 화면, 모바일 표 내부 스크롤과 정보 수정 창도 검증했다. 두 마이그레이션은 연결된 프로젝트에 적용했다.
