# 학교 관리자와 선생님 대시보드

구현일: 2026-10-17

`npm run dev` 실행 후 `http://localhost:3000`에서 로그인한다. `/dashboard`는 사이트 관리자 → 학교 관리자 → 학년 관리자 → 일반 선생님 순서로 실제 권한을 확인해 화면을 선택한다.

## 학교 관리자

- 학교 현황: 선택한 학기의 학년·활성 학급·재적 학생 수, 학교 전체 활성 교사 수와 학년별 담당 현황.
- 학년·담당 배정: 학년 추가, 학급 추가·이름/번호 변경·비활성화, 담임 배정·해제, 학년 관리자 지정·교체. 한 학기 한 교사 한 반, 한 반 한 담임, 학년 관리자 한 명을 DB에서도 검사한다. 학급 비활성화·담임 해제 시 연결된 학년 관리자 권한도 회수한다.
- 선생님 관리: 자기 학교 계정 발급, 표시 이름 수정, 비활성화·재활성화, 비밀번호 초기화. 학교 관리자 계정과 역할은 이 화면에서 변경할 수 없다. 비활성화된 교사는 다시 활성화한 후 현재 학기의 담당을 새로 배정한다.
- 학생 명단: 학년별 검색·페이지 이동, 추가·이름/반 내 번호 수정·같은 학년 반 이동·제외·복구. 실제 삭제 대신 기록을 보존한다.
- 공통 교육과정: 학년별 과목·단원 추가·제목/정렬 순서 수정·비활성화·복구. 적용 학년·학급 범위를 저장 창에 표시한다. 과거 완료 기록은 유지하고 활성 단원만 진도 계산에 포함한다. 완료 기록이 있는 단원을 다른 과목으로 옮기지 않는다.
- 학급 진도: 자기 학교 학급을 선택해 과목별 진도와 단원 상태를 보고 진행 중 학기의 진도를 수정한다.
- 학기 관리: 빈 준비 학기 생성 → 학년·반·담임·학년 관리자 구성 → 시작 확인. 모든 운영 반의 담임과 운영 학년의 관리자가 있어야 시작된다. 현재 진행 학기를 보관하고 준비 학기를 활성화하는 처리는 한 트랜잭션이다. 보관 학기의 원본 자료와 진도는 수정할 수 없다. 현재 버전은 이전 자료 복사·자동 학기 전환을 제공하지 않는다.
- 사용 설명서: 시작 순서, 배정/계정 복구, 학기 보관 안내.

## 일반 선생님

- 담당 반 과목별 단원을 체크·해제한다. 진행 중 학기만 저장할 수 있다. 중복 입력 차단, 저장 중/성공/실패 상태, 실패 시 복원, 버전 충돌 후 최신 조회를 제공한다.
- 진도율은 완료 활성 단원 수 / 활성 단원 수로 계산한다. 학년 비교표에는 진도 막대와 끝점 위의 정수 퍼센트를 표시한다. 과목 이름 아래 막대와 끝점 위 숫자로는 반별 원래 완료/전체 수로 계산한 진도율의 산술평균을 정수로 반올림해 표시한다. 단원 0개는 `단원 미등록`으로 평균 계산에서 제외하며, 계산할 학급이 없으면 `평균: —`로 표시한다. 종합 진도·순위는 없다.
- 학년 비교표에서 같은 학년 다른 반의 과목·단원 진도를 읽기 전용으로 본다. 다른 반의 학생 이름·명단·학생 수는 교사 조회 응답에 포함하지 않는다.
- 자기 반 학생 명단만 검색·페이지 이동으로 조회한다. 일반 선생님에게 학생·과목·단원 편집 API를 허용하지 않는다.
- 현재 학교 소속이 유지되고 실제 담임 배정이 남아 있는 과거 학급은 보관 학기에서도 조회할 수 있다. 소속 또는 배정 해제는 다음 요청부터 적용한다.
- 미배정 계정은 배정 대기 안내·재확인·비밀번호 변경·설명서를 사용할 수 있다.

## 계정과 저장 보안

초기 비밀번호는 `000000`이며 Supabase Auth 서버에서 해시로 저장한다. 발급·초기화 후 최초 변경을 강제한다. 새 비밀번호는 8자 이상이고 영문 대문자·소문자·숫자·특수문자를 모두 포함해야 한다. 비밀번호 원문은 DB 업무 테이블이나 로그에 저장하지 않는다.

초기화·비활성화는 대상의 기존 Auth 세션 ID를 차단 목록에 등록한다. 이후 새 비밀번호를 설정하거나 계정을 재활성화해도 오래된 쿠키가 다시 유효해지지 않는다. Auth 비밀번호 설정 실패 시 차단을 유지하고 재초기화 안내를 제공한다. 계정 생성은 Auth 생성 후 프로필·학교 소속을 DB 트랜잭션으로 등록하며 등록 실패 시 방금 만든 Auth 계정만 정리한다.

`202610170004_school_teacher_workspaces.sql`과 `202610170005_workspace_query_fix.sql`을 순서대로 적용한다. 새 조회·저장 RPC는 사용자 세션과 현재 소속·담당을 검사한다. 학교 ID를 브라우저에서 받아 권한 근거로 쓰지 않는다. 교사 조회 RPC는 자기 반 명단과 같은 학년 진도 응답을 분리한다. 일반 테이블의 쓰기 권한은 열지 않고, 저장 함수가 학교 행 잠금·예상 버전 검사·변경 감사 기록을 처리한다. 학기 전환과 진도 저장도 같은 학교 잠금으로 순서를 보장한다. 보관 학기는 DB 트리거로도 보호한다.

## 테스트 계정

| 아이디 | 역할·배정 |
| --- | --- |
| `school.admin` | 대시보드 테스트 초등학교 학교 관리자 |
| `grade.admin` | 2026학년도 2학기 3학년 관리자, 1반 담임 |
| `test.teacher` | 같은 학기·학년의 2반 일반 담임 |

기존 비밀번호를 사용한다. `npm run teacher:assign-test`는 계정·대상 반의 충돌을 확인하고 `test.teacher`를 배정하며 비밀번호를 초기화하지 않는다. 학년 관리자 권한은 추가하지 않는다.

## 검증

```powershell
npm test
npm run typecheck

```

실연결 검사는 실행 중인 개발 서버와 `.env.local`을 사용한다. 무작위 임시 학교·계정으로 격리, 진도 저장·버전 충돌, 명단/교육과정 편집과 기록 복구, 계정 발급·초기화·최초 변경, 이전 세션 차단, 준비 학기 시작 검토·보관·기록 보존을 검사하고 임시 자료를 정리한다. 영구 테스트 계정의 비밀번호나 학기는 변경하지 않는다.

2026-10-17 단위 테스트 6개, Edge 브라우저 테스트 14개, 타입 검사와 배포 빌드를 통과했다. 실제 Supabase에서 인증·사이트 관리자·학년 관리자 회귀 검사와 새 학교/교사 검증을 모두 통과했고, 임시 학교와 계정 정리도 확인했다. 데스크톱·모바일 화면과 화면 가로 넘침 여부를 확인했다.

학년 관리자 전용 화면의 명단·공통 교육과정 편집 UI, 학기 자료 선택 복사, 사이트 접속 통계는 이 구현에 포함되지 않는다.
